# JourneyForge

行程規劃工具。貼上要拜訪的單位，自動分天、排順序、插午餐、配高鐵車次，排完可以拖曳微調，再輸出成公文用的行程表。

**目前版本：26.02**　（版本公告：`/patch-notes.html`　變更紀錄：`CHANGELOG.md`　使用回饋：`FEEDBACK.md`）

**使用網址：** https://chrischang01538.github.io/JourneyForge/

**新手指南：** https://chrischang01538.github.io/JourneyForge/guide.html　（第一次操作看這份）

**系統說明：** https://chrischang01538.github.io/JourneyForge/sop.html　（管理者與管考用）

## 怎麼用

1. **行程日期** — 填西元日期，星期與民國年會自動換算。每天可以各自設集合時間、集合地點、要不要排午餐，以及解散地點（預設同集合地點，取消勾選就能分開填）。
2. **行程地點** — 一列一個地點，左欄名稱、右欄地址。地址要含縣市。整批名單可以直接從 Excel 複製、貼進任一格，會自動展開成多列。
3. **規劃行程** — 按下去就會分天、決定天內順序、插午餐、配車次。
4. **微調** — 拖曳卡片改順序（可跨天），時間欄即時重算。車程分鐘數、停留時間、名稱地址都能直接改。
5. **輸出** — 「產生 Word 檔」直接下載 .docx；「複製行程表」可貼進 Word；「列印 / 存成 PDF」排成公文格式。
6. **案件連結** — 按「儲存案件」會存進資料庫並產生一個網址，貼給同事就能開同一份行程繼續編。產生 Word 或列印時也會自動存一次。
7. **意見回饋** — 右下角常駐一顆「意見回饋」，就地彈出、不換頁，截圖可以直接 `Ctrl+V` 貼進去。送出後給一組收件編號，內容進試算表的「回饋」分頁。

排程規則（每站停留、拜訪單位午休時段、最晚結束時間等）都在「設定」裡，可依需要調整。出席人員來自不同縣市時，「設定 → 高鐵班次」可以按「＋ 加車次」加開起訖組別，每一組各自建議車次。

## 幾個會即時檢查的事

- 行程有沒有壓到拜訪單位午休（預設 12:00–13:00），撞到的卡片會變紅
- 午餐是不是拖到太晚才開始
- 當天結束時間有沒有超過目標或上限。**超過不會把地點丟著不排**，而是照樣排完並在時間軸與卡片標紅，由你決定要縮短停留還是刪站
- 高鐵車次是否為當天有行駛的班次

## 第一次使用

到「設定 → Google 服務」填入**通行碼**（跟管理者索取），按「測試連線」。看到「連線正常」就好了，之後這台電腦不用再填。

Apps Script 網址已經寫在程式裡，一般不需要動；要改的話在「進階：自訂 Apps Script 網址」裡覆寫，留空就是用內建的。

不填通行碼也能用，只是：地址改用縣市層級粗略定位、午餐放「待訂」占位、臺北－左營以外的區間不提供車次建議。

## 案件

每個案子有一組固定的案件 ID，重複儲存是更新同一列、不會愈存愈多。試算表的「案件」分頁同時存兩份：**Markdown** 給人看、給彙整報告用；**JSON** 給程式還原成可編輯的行程（座標、停留分鐘、手動調整過的車程都在裡面，Markdown 表格存不下這些）。

開啟別人給的案件連結時，自己這邊也要先填通行碼。

## 回饋

使用者從右下角送出的回饋會寫進試算表的「**回饋**」分頁：`收件編號 | 時間 | 使用者 | 版本 | 分類 | 滿意度 | 內容 | 附件 | 環境 | 狀態 | 處理備註`，狀態預設「待處理」。截圖上傳到同一個帳號雲端硬碟的「JourneyForge 回饋附件」資料夾，分頁只存連結。

分頁與資料夾都是第一次用到時自動建立，不必事先開。維護者定期看這個分頁，值得處理的就升成 `FEEDBACK.md` 裡的 `FB-0xx` 正式追蹤。

**收件編號是用列數推算的，不要手動刪列**，會讓編號重複。清資料請改狀態欄。

## 資料庫

高鐵班表存在 Google 試算表的「班表」分頁，一列一班車、十二個站別欄位，任兩站的組合都算得出來。

- 站別欄位：空白＝該站不停；`08:26-08:28`＝到站-開車；單一時間＝起站或終點站
- 行駛日：空白＝每日行駛；有限制才填，`0` 是週日、`1`–`6` 是週一到週六

目前資料為**台灣高鐵 2026/2/2 起適用的常態時刻表**，共 214 班，不含疏運加班車。改點時由管理者重新匯入。

## 維護者備忘

- Apps Script 的指令碼屬性：`SHEET_ID`、`ACCESS_KEY` 必填；`MAPS_KEY` 選填（要啟用 Geocoding API 與 Places API (New)）；`TDX_CLIENT_ID`／`TDX_CLIENT_SECRET` 選填，設了才能用 `refreshTimetable()` 自動更新班表；`FEEDBACK_FOLDER_ID` 不用填，第一次有人送出帶截圖的回饋時程式會自己建資料夾並寫回
- **26.02 起後端用到 `DriveApp`（存回饋截圖）。從舊版更新上來重新部署時會要求重新授權**，要多勾一項雲端硬碟權限，這是正常的
- **改過 `Code.gs` 一定要重新部署**，存檔不會生效。走「部署 → 管理部署作業 → 鉛筆 → 版本：新版本」，網址會沿用；走「新增部署作業」則會產生新網址，得回頭改 `DEFAULT_GAS_URL`
- 只改指令碼屬性（`MAPS_KEY`、`ACCESS_KEY` 等）是即時生效，不用重新部署
- 首次部署：Apps Script →「部署 → 網頁應用程式」，執行身分「我」、存取權「任何人」，複製 `/exec` 結尾的網址
- `index.html` 開頭的 `DEFAULT_GAS_URL` 是給同事用的預設網址。重新部署換網址時改這一行就好
- **通行碼絕對不要寫進任何檔案。** repo 是公開的，網址也是公開的，通行碼是唯一的一道鎖，請用 16 字元以上的隨機字串
