# JourneyForge

訪視行程規劃工具。貼上要訪視的單位，自動分天、排順序、插午餐、配高鐵車次，排完可以拖曳微調，再輸出成公文用的行程表。

**使用網址：** https://chrischang01538.github.io/JourneyForge/

---

## 怎麼用

1. **訪視日期** — 填西元日期，星期與民國年會自動換算。每天可以各自設集合時間與集合地點。
2. **行程地點** — 一列一個地點，左欄名稱、右欄地址。地址要含縣市。整批名單可以直接從 Excel 複製、貼進任一格，會自動展開成多列。
3. **規劃行程** — 按下去就會分天、決定天內順序、插午餐、配車次。
4. **微調** — 拖曳卡片改順序（可跨天），時間欄即時重算。車程分鐘數、停留時間、名稱地址都能直接改。
5. **輸出** — 「產生 Word 檔」直接下載 .docx；「複製行程表」可貼進 Word；「列印 / 存成 PDF」排成公文格式。
6. **案件連結** — 按「儲存案件」會存進資料庫並產生一個網址，貼給同事就能開同一份行程繼續編。產生 Word 或列印時也會自動存一次。

排程規則（每廠停留、廠方午休時段、最晚結束時間等）都在「設定」裡，可依需要調整。

## 幾個會即時檢查的事

- 訪視時段有沒有壓到廠方午休（預設 12:00–13:00），撞到的卡片會變紅
- 午餐是不是拖到太晚才開始
- 當天結束時間有沒有超過目標或上限
- 高鐵車次是否為當天有行駛的班次

## 第一次使用

到「設定 → Google 服務」填入**通行碼**（跟管理者索取），按「測試連線」。看到「連線正常」就好了，之後這台電腦不用再填。

Apps Script 網址已經寫在程式裡，一般不需要動；要改的話在「進階：自訂 Apps Script 網址」裡覆寫，留空就是用內建的。

不填通行碼也能用，只是：地址改用縣市層級粗略定位、午餐放「待訂」占位、臺北－左營以外的區間不提供車次建議。

## 案件

每個案子有一組固定的案件 ID，重複儲存是更新同一列、不會愈存愈多。試算表的「案件」分頁同時存兩份：**Markdown** 給人看、給彙整報告用；**JSON** 給程式還原成可編輯的行程（座標、停留分鐘、手動調整過的車程都在裡面，Markdown 表格存不下這些）。

開啟別人給的案件連結時，自己這邊也要先填通行碼。

## 資料庫

高鐵班表存在 Google 試算表的「班表」分頁，一列一班車、十二個站別欄位，任兩站的組合都算得出來。

- 站別欄位：空白＝該站不停；`08:26-08:28`＝到站-開車；單一時間＝起站或終點站
- 行駛日：空白＝每日行駛；有限制才填，`0` 是週日、`1`–`6` 是週一到週六

目前資料為**台灣高鐵 2026/2/2 起適用的常態時刻表**，共 214 班，不含疏運加班車。改點時由管理者重新匯入。

## 維護者備忘

- Apps Script 的指令碼屬性：`SHEET_ID`、`ACCESS_KEY` 必填；`MAPS_KEY` 選填（要啟用 Geocoding API 與 Places API (New)）；`TDX_CLIENT_ID`／`TDX_CLIENT_SECRET` 選填，設了才能用 `refreshTimetable()` 自動更新班表
- **改過 `Code.gs` 一定要重新部署**，存檔不會生效。走「部署 → 管理部署作業 → 鉛筆 → 版本：新版本」，網址會沿用；走「新增部署作業」則會產生新網址，得回頭改 `DEFAULT_GAS_URL`
- 只改指令碼屬性（`MAPS_KEY`、`ACCESS_KEY` 等）是即時生效，不用重新部署
- 首次部署：Apps Script →「部署 → 網頁應用程式」，執行身分「我」、存取權「任何人」，複製 `/exec` 結尾的網址
- `index.html` 開頭的 `DEFAULT_GAS_URL` 是給同事用的預設網址。重新部署換網址時改這一行就好
- **通行碼絕對不要寫進任何檔案。** repo 是公開的，網址也是公開的，通行碼是唯一的一道鎖，請用 16 字元以上的隨機字串
